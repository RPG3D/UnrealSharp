# Mono Runtime Integration for UnrealSharp

Mono runtime support for UnrealSharp, enabling C# scripting on **Android** and **iOS** where CoreCLR is not available. The vast majority of the implementation (C++ runtime host, managed C# compatibility, build system, and packaging pipeline) was generated by AI, guided by analysis of the [UnrealCSharp](https://github.com/UnrealCSharp/UnrealCSharp) plugin's Mono embedding patterns. The integration adds a dual-runtime architecture — CoreCLR (`hostfxr`) remains the default for Win64/Mac, while Mono (`libmonosgen-2.0`) is opt-in via `bUseMono=true` in `DefaultEngine.ini`.

Reference: [UnrealCSharp](https://github.com/UnrealCSharp/UnrealCSharp) plugin (Mono embedding patterns).

## Features

- **Dual runtime**: CoreCLR (`bUseMono=false`) and Mono (`bUseMono=true`) coexist via `#if UNREALSHARP_MONO`, no code duplication required.
- **iOS AOT+INTERP**: Apple's W^X policy forbids JIT — Mono runs in interpreter mode with AOT-compiled BCL trampolines.
- **Android JIT**: Full JIT support via `libmonosgen-2.0.so`, packaged through APL.
- **Managed DLLs in PAK**: Project assemblies are staged into the PAK as UFS and can be hot-updated alongside game assets. BCL is staged as NonUFS outside the PAK (tied to the Mono runtime version).
- **Saved/ override**: `Saved/Managed/{Platform}/` provides a writable override directory for iterating on DLLs without repackaging.
- **UFS assembly loading**: `mono_install_assembly_preload_hook` with `FFileHelper::LoadFileToArray` (pak-aware) replaces `mono_assembly_open` (POSIX `fopen`).
- **Cross-platform managed DLLs**: C# assemblies built for Win64 work on Android and iOS — the IL is platform-agnostic.

## Quick Start

### 1. Enable Mono

In `Config/DefaultEngine.ini`:

```ini
[UnrealSharp]
bUseMono=true
```

### 2. Build the Game target (required once)

UBT must compile the `Game` target first to generate C# glue for non-editor builds:

```bash
# Windows
RunUAT.bat BuildCookRun -project=SharpDemo.uproject -Build -Target=SharpDemo -TargetPlatform=Win64 -ClientConfig=Development
```

### 3. Compile managed DLLs

```bash
# Build UnrealSharp bindings
dotnet publish Plugins/UnrealSharp/Managed/UnrealSharp/UnrealSharp.sln \
  -c Release -p:UseMonoRuntime=true --no-self-contained \
  -p:PublishDir="Content/Managed/Win64" \
  -p:UETargetType=Game -p:UEBuildConfig=Shipping

# Build user scripts
dotnet publish Script/ManagedSharpDemo.sln \
  -c Release -p:UseMonoRuntime=true --no-self-contained \
  -p:PublishDir="Content/Managed/Win64" \
  -p:UETargetType=Game -p:UEBuildConfig=Shipping
```

Managed DLLs are cross-platform — copy the Win64 output to other platform directories:

```bash
cp Content/Managed/Win64/* Content/Managed/Android/
```

Also copy the load order manifest:

```bash
cp Binaries/Managed/net10.0/UserCode.LoadOrder.json Content/Managed/Android/
```

### 4. Package with UAT

```bash
RunUAT.bat BuildCookRun -project=SharpDemo.uproject \
  -Build -Target=SharpDemo -TargetPlatform=Android -ClientConfig=Development \
  -Cook -Pak -Stage -Archive -package
```

## Performance

Test: 1M calls to `MathLibrary.PointsAreCoplanar` (C#→C++ interop with 8 `FVector` parameters), measured in editor on Win64.

```csharp
var begin = MathLibrary.Now();
for (int i = 0; i < 1024 * 1024; ++i)
{
    var points = new List<FVector> { new(0,0,0), new(0,0,1), new(0,1,0), new(0,1,1),
                                    new(1,0,0), new(1,0,1), new(1,1,0), new(1,1,1) };
    MathLibrary.PointsAreCoplanar(points, 0.01f);
}
var elapsed = MathLibrary.GetTotalSeconds(MathLibrary.Subtract_DateTimeDateTime(MathLibrary.Now(), begin));
```

| Runtime | Time (1M calls) | Relative | Notes |
|---------|----------------|----------|-------|
| **CoreCLR** | ~0.42s | 1.0× | Direct function pointer via `MethodHandle.GetFunctionPointer()` |
| **Mono JIT** | ~0.68s | 1.6× | Reflection invoke via `MethodInfo.Invoke()` |
| **Mono INTERP** | ~2.2s | 5.2× | Bytecode interpreter (required on iOS) |

*UnrealSharp 20260321, .NET 10, Win64 Editor. Mono INTERP mode via `mono_interp.flag` file.*

## How it works

### Packaging flow

```
① dotnet publish  project DLLs → Content/Managed/{Platform}/
② UAT BuildCookRun:
   - BCL DLLs are staged as NonUFS (outside PAK) via MonoSDK.Build.cs RuntimeDependencies
   - Project DLLs are staged as UFS (inside PAK) via MonoSDK.Build.cs RuntimeDependencies
   - LoadOrder.json tells UnrealSharp which assemblies to load
```

### Assembly loading

Mono loads assemblies through a UE-aware preload hook:

1. `Saved/Managed/{Platform}/` — writable override (highest priority, for iteration)
2. `Content/Managed/{Platform}/` — PAK-resident project DLLs
3. `Source/ThirdParty/MonoSDK/{Platform}/runtime/` — BCL (NonUFS, outside PAK)

The preload hook uses `FFileHelper::LoadFileToArray` which transparently reads from both the OS filesystem and PAK files.

### Editor hot-reload

Under Mono, hot-reload uses `dotnet build` instead of the Roslyn backend (`UnrealSharp.Editor.dll` is incompatible with the Mono BCL). File changes trigger a full `dotnet build` cycle.

## Third-Party Dependencies

**MonoSDK** — prebuilt Mono runtime libraries and BCL for all supported platforms.

| | |
|---|---|
| **GitHub** | [RPG3D/MonoSDK](https://github.com/RPG3D/MonoSDK) |
| **Clone location** | `Source/ThirdParty/MonoSDK/` |

The MonoSDK submodule provides `libmonosgen-2.0`, `libcoreclr`, BCL DLLs, and platform-specific libraries (iOS AOT stubs, Android APL XML, macOS interop dylibs).

## Key files

| File | Purpose |
|------|---------|
| `Source/UnrealSharpCore/Private/DotNet/CSMonoRuntime.h/cpp` | Mono initialization, UFS assembly loading, platform AOT modes |
| `Source/UnrealSharpCore/Private/DotNet/CSDotNetRuntimeHost_Mono.cpp` | Mono host entry point (`InitializeMonoHost`) |
| `Source/ThirdParty/MonoSDK/MonoSDK.Build.cs` | BCL NonUFS + project UFS RuntimeDependencies |
| `Build/Scripts/BuildCommands/PackageProjectMono.cs` | Mono packaging command |
| `Build/Scripts/Utilities/MonoProjectSettings.cs` | Read `bUseMono` from `DefaultEngine.ini` |
| `Managed/Directory.Build.props` | Define `UNREALSHARP_MONO` when `UseMonoRuntime=true` |
