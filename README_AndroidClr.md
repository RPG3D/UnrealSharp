# Android CoreCLR Support for UnrealSharp

Android (arm64) CoreCLR host for UnrealSharp. Android has **no hostfxr**, so the
runtime is bootstrapped via the raw `coreclr_initialize` / `coreclr_create_delegate`
C API (`coreclrhost.h`) instead of the desktop hostfxr path. Managed IL is
platform-agnostic — the same C# scripts authored for Win64 run on Android.

Android is a first-class supported platform (no opt-in switch, no Mono-style macro),
dispatched with a plain `#if PLATFORM_ANDROID` consistent with how Win64/Mac are handled.

Reference: [AndroidClrDemo](https://github.com/RPG3D/CoreClrDemo/tree/main/AndroidClrDemo) (`app/src/cpp/clrdemo.c`) —
verified standalone demo of the raw CoreCLR hosting flow on Android.

## What it does

- **Raw CoreCLR host** (`CSDotNetRuntimeHost_Android.cpp`): bootstraps CoreCLR via
  `coreclr_initialize` (TPA / APP_CONTEXT_BASE_DIRECTORY / NATIVE_DLL_SEARCH_DIRECTORIES),
  `coreclr_create_delegate` for the `UnrealSharp.Plugins.Main.InitializeUnrealSharp`
  entry point, `coreclr_set_error_writer` → logcat diagnostics.
- **Compile-time link** (`CoreClrSDK.Build.cs`): `libcoreclr.so` is linked at compile
  time (NDK `-l`), so the C++ host calls `coreclr_*` directly via prototypes — no
  dlopen / GetDllExport string lookup.
- **Assembly extraction with xxHash** (`EnsureRuntimeDllsExtracted`): BCL (NonUFS) +
  project DLLs (UFS/PAK) are extracted to `ProjectSavedDir/Managed/Android/` (a real
  OS path CoreCLR can mmap). A size pre-check + xxHash sidecar (`DllHash/<name>.txt`)
  skips unchanged files — subsequent launches are fast, hot-updated DLLs re-extract.
  TPA is built from the PAK/NonUFS **source** file names (not the extraction dir) so
  DLLs removed from the PAK don't linger.
- **GC-safe assembly loading** (`CSManager.cpp`): Android packaged builds force
  non-collectible assemblies + `RF_MarkAsRootSet` (CSManager is disregard-for-GC;
  runtime-loaded assemblies must be rooted).
- **`PluginLoadContext` fallback** (`PluginLoadContext_Android.cs`): `AssemblyDependencyResolver`
  is unsupported on the raw coreclr host (no hostpolicy) — falls back to directory-based
  resolution.
- **Editor-only code stripped** (`DisableWithEditor`): `MSBuildLocator` (editor-only)
  is gated by `#if WITH_EDITOR` + conditional `PackageReference`, so packaged builds
  don't reference it (Android has no dotnet SDK on PATH).

## Supported platforms

| Platform | Host | Runtime Library | Status |
|----------|------|-----------------|--------|
| Win64 Editor/Packaged | hostfxr | `hostfxr.dll` | ✅ Unchanged |
| Mac Editor/Packaged | hostfxr | `libhostfxr.dylib` | ✅ Unchanged |
| Android (arm64) | raw `coreclr_initialize` | `libcoreclr.so` | ✅ Verified |

## Prerequisites

- **CoreClrSDK binaries** — populate once via the fetch script (binaries are git-ignored):

  ```bash
  # Windows
  Plugins\UnrealSharp\Source\ThirdParty\CoreClrSDK\FetchCoreClrSDK.bat
  # macOS / Linux
  Plugins/UnrealSharp/Source/ThirdParty/CoreClrSDK/FetchCoreClrSDK.sh
  ```

  Downloads `Microsoft.NETCore.App.Runtime.android-arm64` (default 10.0.9) from NuGet
  and extracts `.so` → `Android/lib/`, BCL `.dll` → `Android/runtime/`.

## Packaging flow

### 1. Build the Game target (generates C# glue)

`UnrealSharp.csproj` compiles `Intermediate/UnrealSharp/UHT/Game/**/*.cs` (UHT-generated
bindings). Editor builds only generate `UHT/Editor/`; **Game-target builds generate
`UHT/Game/`**, which the runtime publish needs.

```bash
<EngineDir>/Engine/Build/BatchFiles/Build.bat <GameTarget> Win64 Development \
  -Project="<ProjectDir>/<GameName>.uproject" -WaitMutex
```

### 2. Publish managed DLLs (cross-platform IL, `--no-self-contained`)

```bash
# Bindings
dotnet publish <PluginDir>/Managed/UnrealSharp/UnrealSharp.sln -c Release --no-self-contained \
  -p:DisableWithEditor=true -p:UETargetType=Game -p:UEBuildConfig=Shipping \
  -p:PublishDir="<ProjectDir>/Content/Managed/Android"

# User scripts
dotnet publish <ProjectDir>/Script/<GameName>.sln -c Release --no-self-contained \
  -p:DisableWithEditor=true -p:UETargetType=Game -p:UEBuildConfig=Shipping \
  -p:PublishDir="<ProjectDir>/Content/Managed/Android"

# LoadOrder manifest (not generated by publish — copy from Binaries/Managed)
copy <ProjectDir>/Binaries/Managed/net10.0/UserCode.LoadOrder.json \
  <ProjectDir>/Content/Managed/Android/
```

`DisableWithEditor=true` strips editor-only code (`MSBuildLocator`). Managed IL is
platform-agnostic — same output as Win64. `UserCode.LoadOrder.json` is generated by
the build tool separately and must be copied manually.

### 3. Package the APK

```bash
<EngineDir>/Engine/Build/BatchFiles/RunUAT.bat BuildCookRun \
  -project="<ProjectDir>/<GameName>.uproject" -Build -Target=<GameTarget> \
  -TargetPlatform=Android -ClientConfig=Development -Cook -Pak -Stage -Archive -package -nocompileuat
```

`CoreClrSDK.Build.cs` + `CoreClrSDK_APL.xml` stage:
- native `.so` → APK `lib/arm64-v8a/` (APL `copyDir`)
- BCL `.dll` → NonUFS (outside PAK)
- project `.dll` / `.pdb` / `.json` → UFS (inside PAK, hot-updatable)

### 4. Install & run

```bash
adb install -r <APK path>
adb shell am start -n <package>/<activity>
adb logcat -s LogUnrealSharp:I LogUnrealSharpPlugins:I DOTNET:I
```

Expected:
```
[CoreClr-Android] Runtime dir: .../Saved/Managed/Android
[CoreClr-Android] TPA built: N chars, N assemblies
[CoreClr-Android] coreclr_initialize => 0x0 (domain 1)
[CoreClr-Android] coreclr_create_delegate => 0x0
UnrealSharp initialized successfully.
Successfully loaded plugin: ...
```

## Non-goals / future work

- **iOS** — interpreter/AOT; separate effort.
- **Android x86 / armeabi-v7a** — arm64-v8a only.
- **Remote managed debugging on device** — not implemented.
- **PAK memory loading** (no extraction) — `external_assembly_probe` mechanism verified
  feasible but blocked on TPA path format. Current xxHash extraction is the working fallback.
