UnrealSharp 移动端实现与验证记录

用途与范围
保留本次移植补丁的理由、当前代码归属和验证边界，供后续更新上游时逐项复核。
长期移植思路见 MOBILE_PORTING_GUIDE.md，发布操作见 README.md。
本记录随代码维护，不继续累加临时提交号、重试过程或设备操作流水。

上游基线为 main 947b6ae5，mobile20261021作为问题与方案参考。
目标为Android/iOS arm64，Mono与CoreCLR。托管项目目标为net10.0。
本次使用现有本地SDK载荷：Mono .NET 10、CoreCLR .NET 11；运行时源码核验依据其载荷记录。
DotNetRuntimeSDK固定在86976ca8，相对66a9523c只调整一处managed staging规则。

当前代码归属及补丁理由

1. 原生运行时
Source/UnrealSharpCore/Private/DotNet/CSDotNetRuntimeHost.cpp
Source/UnrealSharpCore/Public/DotNet/CSDotNetRuntimeHost.h
  .cpp中的桌面实现保留上游正文，只增加所需头文件和编译条件；头文件按后端声明状态。
  移动端不依赖桌面hostfxr。各后端自行实现InitializeManagedRuntime和ShutdownManagedRuntime。
Source/UnrealSharpCore/Private/DotNet/CSDotNetRuntimeHost_Mono.cpp
  Mono embedding、UFS程序集preload、iOS解释执行和CoreLib AOT注册、启动与cleanup。
  preload保留字节复制与image引用释放约定。dl fallback直接透传Mono已转换的原生RTLD flags。
Source/UnrealSharpCore/Private/DotNet/CSDotNetRuntimeHost_MobileCoreClr.cpp
  原始CoreCLR宿主、TPA、CoreLib probe、移动平台配置、启动与shutdown。
  从UFS准备物理缓存。逻辑路径负责UE I/O，物理路径负责实际缓存比较和原子替换。
  probe字节与runtime contract维持运行时生命周期；删除旧缓存项，避免更新安装混入旧程序集。

2. 托管入口及程序集加载
Managed/UnrealSharp/UnrealSharp.Plugins/Main.cs
Managed/UnrealSharp/UnrealSharp.Plugins/Main_Mobile.cs
  通用初始化与错误缓冲在Main.cs；移动入口和HasHostPolicy状态在Main_Mobile.cs。
  宿主能力决定是否使用桌面hostpolicy/MSBuild注册路线。
Managed/UnrealSharp/UnrealSharp.Plugins/Plugin.cs

  避免无hostpolicy时构造AssemblyDependencyResolver，也避免直接忽略调用者提供的路径。

验证结果及适用范围

2026年11月19日，使用独立SharpDemo验证副本、本机UE5.9和缓存SDK完成验证。
移动端使用arm64设备：Android 24122RKC7C、iPad Air 7/iPadOS 27.2.1。
组合                  编译与发布    签名打包    安装、Gameplay与SMOKE PASS
Android Mono          通过          通过        通过
Android CoreCLR       通过          通过        通过
iOS Mono              通过          通过        通过
iOS CoreCLR           通过          通过        通过

结构整理后四组合均重新发布、原生构建、签名打包和安装；重用既有Cook资源，未修改游戏资产。
APK通过apksigner验证，.app通过codesign深度严格验证；分别核对Mono/CoreCLR native运行时内容互斥。
Android CoreCLR另验证开始新游戏、视频播放及跳过后的引擎场景、角色和对白。iPad CoreCLR持续运行超过两分钟。
这些结果覆盖已执行的启动和场景路径，不代表完整游戏流程、长时间稳定性或所有设备兼容性通过。

结构整理前后29项生成器测试通过。
两版生成器的49份包装文件逐字一致，其中47份来自生产Interop输入、2份来自测试输入。
已有解释器分配复现显示旧分配48/64次未满足16字节对齐；两套实际生成器输出在256次对齐检查中全部通过。
构建锁夹具覆盖并发、符号链接、弃锁、失败释放与无Project命令行路径。
发布夹具覆盖失败保留旧输出、BCL-only恢复、native资产拒绝、RID、发布戳与引用路径。
加载夹具覆盖物理目录、外部依赖、Default共享和实体collectible程序集；它们不等于移动UFS collectible完整验证。

初轮在本机CoreCLR Mac Editor下通过UHT及完整Editor构建。
结构整理后的桌面宿主正文与上游一致，但未追加完整桌面原生目标重建；旧缓存的独立检查因PCH/UHT路径失效未形成有效编译证据。
验证副本使用本机引擎需要的两个可选UGP空钩子及文件式Cook，这些条件不属于插件的通用部署要求。
