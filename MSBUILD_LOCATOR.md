# Microsoft.Build.Locator.dll on Android (CoreCLR)

Why `Microsoft.Build.Locator.dll` must NOT ship in an Android/packaged build, how it
leaks in despite the `DisableWithEditor` gate, and how to verify it's gone. Written
after debugging a device crash on the `MobileClr20260724` branch (2026-07-26).

## Symptom (on device)

App installs and CoreCLR boots fine, then crashes at the managed entry point:

```
[CoreClr-Android] coreclr_initialize => 0x0 (domain 1)      ← CoreCLR OK
[CoreClr-Android] coreclr_create_delegate => 0x0             ← delegate OK
DOTNET: System.InvalidOperationException: Path to dotnet executable is not set.
        The probed variables were: DOTNET_ROOT, DOTNET_HOST_PATH,
        DOTNET_MSBUILD_SDK_RESOLVER_CLI_DIR and PATH. Make sure, that at least one
        of the listed variables points to the existing dotnet executable.
   at Microsoft.Build.Locator.DotNetSdkLocationHelper.ResolveDotnetPathCandidates()
   ...
   at UnrealSharp.Plugins.Main.InitializeUnrealSharp(...) in ...Main.cs:line 27
Fatal error: [CSDotNetRuntimeHost_Mobile.cpp:417] Failed to initialize UnrealSharp
             (managed entry returned false)!
```

`Main.cs:25-37` calls `MSBuildLocator.QueryVisualStudioInstances()` inside an
`#if WITH_EDITOR` block. On Android there is no dotnet SDK, so MSBuildLocator's static
`Lazy` initializer throws. For that code to have run, **`WITH_EDITOR` was defined when
`UnrealSharp.Plugins.dll` was compiled** - which must not happen for a Game/Shipping build.

## The misleading "obvious" answer (true, but not sufficient)

`UnrealSharp.Plugins.csproj` does gate MSBuildLocator correctly:

```xml
<DefineConstants>WITH_EDITOR</DefineConstants>
<DefineConstants Condition="'$(DisableWithEditor)' == 'true'">
    $(DefineConstants.Replace('WITH_EDITOR;', '').Replace('WITH_EDITOR', ''))
</DefineConstants>
...
<PackageReference Include="Microsoft.Build.Locator"
                  Condition="'$(DisableWithEditor)' != 'true'" />
```

With `-p:DisableWithEditor=true`, `WITH_EDITOR` is removed from `DefineConstants` and
the `PackageReference` is excluded. Verified: `dotnet msbuild UnrealSharp.Plugins.csproj
-p:DisableWithEditor=true -getProperty:DefineConstants` -> `;DEBUG` (no `WITH_EDITOR`),
and `-getItem:PackageReference` -> `[]` (empty). So a CLEAN publish of `UnrealSharp.Plugins`
produces a `Plugins.dll` with no `WITH_EDITOR` code and no MSBuildLocator reference.

**This gate alone is not sufficient** because of the reference chain below.

## Real root cause: plugin-local Binaries + the cook build

`UnrealSharp.Shared.props` (imported by every Script project - `ManagedSharpDemo`,
`Pal3.Core`, `Engine`, `Pal3.Game`, ...) references the UnrealSharp assemblies by
**HintPath to the plugin-local Binaries dir**, not the project's:

```xml
<Reference Include="UnrealSharp.Plugins">
  <HintPath>$(UnrealSharpPluginDir)Binaries\Managed\$(TargetFramework)\UnrealSharp.Plugins.dll</HintPath>
</Reference>
<!-- $(UnrealSharpPluginDir) = Plugins/UnrealSharp/ -->
```

So Script references whatever `UnrealSharp.Plugins.dll` is at
`Plugins/UnrealSharp/Binaries/Managed/net10.0/UnrealSharp.Plugins.dll`.

UAT `BuildCookRun` builds the **Editor** target first (for cook), which builds the managed
assemblies WITH `WITH_EDITOR` into that plugin-local Binaries dir (alongside
`Microsoft.Build.Locator.dll`). Unless a subsequent clean `DisableWithEditor` publish
**overwrites** those files, the Script publish resolves the editor's `WITH_EDITOR`
`Plugins.dll`, pulls `Microsoft.Build.Locator.dll` in as a **transitive dependency**,
and copies both to `Content/Managed/Android` -> packaged -> crash on device.

In other words: the `DisableWithEditor` gate on `Plugins.csproj` only takes effect when
`Plugins.csproj` is actually (re)built with `DisableWithEditor=true`. If the
plugin-local `Plugins.dll` is the editor/cook build's `WITH_EDITOR` artifact, Script
links against it and the gate is bypassed entirely.

The `UnrealSharp.AOT.props` import (conditioned on `Exists`) is a no-op (file absent)
and is NOT involved. The `UE5Rules.Defines.props` generated by
`PreprocessorExporter.ExportBuildDefines()` carries only `UE_X_Y_OR_LATER`-style
version defines (no `WITH_EDITOR`), so it is NOT the leak vector either.

## Fix

Publish UnrealSharp so it writes a clean `DisableWithEditor` build to the plugin-local
Binaries dir (overwriting the cook's `WITH_EDITOR` artifacts), remove the stale
MSBuildLocator, THEN publish Script. Also: serial build (`-m:1`) + `DOTNET_DISABLE_BUILD_SERVERS=1`
(see [[android-coreclr-packaging]] / README_AndroidClr.md for the parallel-race gotcha).

```bash
export DOTNET_DISABLE_BUILD_SERVERS=1
PROJ="D:/UEProject/SharpDemo"

# 1. Publish UnrealSharp WITHOUT -p:UseDefaultOutputPath=true.
#    Directory.Build.props sets OutputPath = $(SolutionDir)..\..\Binaries\Managed\
#    (plugin-local) when UseDefaultOutputPath != true, so this writes clean DLLs
#    to Plugins/UnrealSharp/Binaries/Managed/net10.0/ (where Shared.props HintPaths).
#    WITH UseDefaultOutputPath=true it would build to bin/Release and NOT update
#    plugin-local Binaries - leaving the cook's WITH_EDITOR DLLs in place.
dotnet publish "$PROJ/Plugins/UnrealSharp/Managed/UnrealSharp/UnrealSharp.sln" \
  -c Release --no-self-contained -m:1 \
  -p:PublishDir="$PROJ/Content/Managed/Win64" \
  -p:UETargetType=Game -p:UEBuildConfig=Shipping -p:DisableWithEditor=true

# 2. Remove any stale MSBuildLocator from plugin-local Binaries.
rm -f "$PROJ/Plugins/UnrealSharp/Binaries/Managed/net10.0/Microsoft.Build.Locator.dll"

# 3. Publish Script (now resolves the clean Plugins.dll -> no MSBuildLocator transitive).
dotnet publish "$PROJ/Script/ManagedSharpDemo.sln" \
  -c Release --no-self-contained -m:1 \
  -p:PublishDir="$PROJ/Content/Managed/Win64" \
  -p:UETargetType=Game -p:UEBuildConfig=Shipping -p:DisableWithEditor=true

# 4. Copy LoadOrder manifests + xcopy Win64 -> Android, then BuildCookRun.
```

## Verify it's gone (do this before every package)

```bash
# Must be ABSENT. If present, the publish above didn't clean plugin-local Binaries.
ls "$PROJ/Content/Managed/Android/Microsoft.Build.Locator.dll"   # -> No such file
# After packaging, confirm it's not staged:
grep -ci "Microsoft.Build.Locator" \
  "$PROJ/Saved/StagedBuilds/Android/Manifest_UFSFiles_Android.txt"   # -> 0
```

On device, success looks like:

```
[CoreClr-Android] coreclr_initialize => 0x0 (domain 1)
[CoreClr-Android] coreclr_create_delegate => 0x0
UnrealSharp initialized successfully.                 <- no InvalidOperationException
Successfully loaded plugin: 'Pal3.Game' ...           <- all plugins load
```

## Related: editor-only APIs in game code

Cleaning `WITH_EDITOR` out of the package can surface game code that relied on the
leak. On this branch `Script/Engine/Core/Implementation/UEGameEntity.cs` used
`AActor.GetActorLabel/SetActorLabel` (editor-only bindings, absent from the Game glue)
unconditionally - it only compiled before because `WITH_EDITOR` was leaking. Fixed by
gating those calls with `#if WITH_EDITOR` and using `_actor.Name.ToString()`
(`UObject.Name` returns `FName`, which has an implicit `string` conversion) as the
Game-build fallback. Audit the Pal3 port for other editor-only API usage when
cleaning `WITH_EDITOR`.
